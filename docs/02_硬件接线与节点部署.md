# 02 硬件接线与节点部署

## 1. 物料清单

**每个节点 = CH573F 最小系统板 + MQ 系列传感器模块 + 有源蜂鸣器**，就这三样。
（本工程不涉及 OLED、也不涉及按键，固件里没有这两部分代码。）

| 序号 | 物品 | 数量 | 说明 |
|---|---|---|---|
| 1 | **CH573F 最小系统板** | 若干个（3~6） | ★ 必备。一个房间一个，主控 + BLE |
| 2 | **MQ 系列气敏传感器模块**（MQ-2 等） | 与节点同数量 | ★ 必备。AO → PA4，DO → PA5 |
| 3 | **有源蜂鸣器**（3.3V，带驱动板最好） | 每节点 1 | ★ 本机报警发声，接 PB15 |
| 4 | ESP32-S3 开发板 | 1 | 网关，需 16MB Flash（工程按 3MB 应用分区配置） |
| 5 | USB-TTL 串口模块 | 1~2 | 看节点/网关日志（也可以直接用 WCH-LinkE 的串口） |
| 6 | WCH-LinkE 下载器 | 1 | 烧 CH573F |

> 只有板子 + 传感器也能跑通全流程：采样、判报警、BLE 上报、网页报警、云端下发指令都正常，
> 唯一差别是**节点本身不会响**（本地报警只能靠串口日志看 `ALM=1`）。
> 所以第 3 项（一两块钱的有源蜂鸣器）建议补上，否则"报警器"这个说法在答辩时容易被质疑。

## 2. 节点接线表（CH573F）

> 引脚分配：AO 用 **PA4**（ADC AIN0）、DO 用 **PA5**、蜂鸣器用 **PB15**，调试串口占 PB4/PB7。
> PA8 / PA9 / PA12~PA15 目前空着，可以用来扩第二路传感器。

| 功能 | 引脚 | 方向 | 备注 |
|---|---|---|---|
| MQ 传感器 **AO**（模拟输出） | **PA4**（ADC AIN0） | 模拟输入 | 模块 3.3V 供电可直接接；5V 供电必须分压 |
| MQ 传感器 **DO**（数字输出，可选） | **PA5** | 输入（上拉） | 不用就在 `node_cfg.h` 里把 `NODE_HAS_DO` 改 0 |
| 蜂鸣器 | **PB15** | 输出（高电平响） | 经 NPN 三极管/驱动模块；若你的板子 PB15 上有 LED，也能当指示灯 |
| 调试串口 | **PB7 = TXD0，PB4 = RXD0** | — | 115200 8N1，USB-TTL 的 RX 接 PB7、TX 接 PB4，共地 |
| 传感器供电 | VCC / GND | — | 见下面"供电"一节 |

### 2.1 传感器供电：强烈建议 5V

MQ-2 的加热丝额定 **5.0V / 约 31Ω（≈800mW）**：

| 供电 | 加热功率 | 结果 |
|---|---|---|
| 5V | ≈810 mW | 正常工作，响应快、漂移小 |
| 3.3V | ≈350 mW（只有 43%） | 膜温不够：基线偏低、漂移大、**几乎不响应气体** |

> 如果你现在接的是 3.3V 而且怎么吹都不动，第一件事就是改成 5V。

**5V 供电时 AO 必须分压**（AO 最高会到 5V，直接进 3.3V 的 MCU 会打坏引脚）：

```
  MQ-2 AO ──[ 10kΩ ]──●──[ 10kΩ ]── GND
                      │
                      └──────────────► PA4
```

然后改 `node_cfg.h`：

```c
#define NODE_MODULE_VCC_MV   5000    /* 模块接 5V */
#define NODE_AO_DIV_X100     200     /* 10k+10k 对半分压；10k+20k 写 300 */
```

3.3V 直连时保持默认（`3300` + `100`）。

> **DO 也要注意**：DO 是模块上比较器的数字输出，5V 供电时它的高电平也是 5V。
> 接到 PA5 之前同样建议分压（和 AO 一样的 10k+10k），或者至少串一只 10kΩ 限流；
> 3.3V 供电时可以直接接。只用 AO 判报警的话，把 `NODE_HAS_DO` 改成 0 最省事。

### 2.2 蜂鸣器接法

```
  VCC(3.3V) ──── 蜂鸣器(+) 
  蜂鸣器(-) ──── C
                  SS8050 (NPN)
  PB15 ──1kΩ─── B
  GND ───────── E
```

PB15 高 = 响。用现成的"有源蜂鸣器模块"更简单（模块一般标 VCC/GND/IN，IN 接 PB15）。
不要就用 `NODE_HAS_BUZZER 0` 关掉。

### 2.3 怎么知道节点当前状态？

节点用**串口日志 + 蜂鸣器**当状态指示：

| 现象 | 含义 |
|---|---|
| 串口每秒一行 `[NODE N01] t=12s ADC=... ALM=0 WARM TX=0` | 正常运行；`WARM` 表示还在预热 |
| 串口出现 `>>> [NODE N01] 报警! ...` | 判定为报警（同时上报云端） |
| 串口出现 `<<< [NODE N01] 报警解除 ...` | 报警解除 |
| 上电后 30 秒处蜂鸣器"嘀"一声（150ms） | 预热结束、基线建立，**从现在开始才是有效检测** |
| 蜂鸣器"嘀—嘀—嘀"断续响 | 报警中（网页消音后停，但数据照常上报） |
| 蜂鸣器连续长鸣 3 秒 | 网页下发了 `T` 自检 |

没接蜂鸣器也没关系：网页上的红色横幅、Δ% 曲线和事件流同样能说明问题。

## 3. 三块板子的身份：节点编号 + 传感器型号

文件：`node_ch573f\node\SmokeNode\APP\include\node_cfg.h`

```c
#define NODE_TAG     "N01"     /* ★ 每块板子不一样：N01 / N02 / 厨房 / 客厅 */
#define NODE_MODEL   "MQ-2"    /* ★ 你插的是哪个型号就写哪个 */
```

身份写在 `node_ch573f\node\SmokeNode\APP\include\node_cfg.h` 里，
但**不用改源码**：编译脚本可以覆盖这两个默认值，一条命令出一份固件。

本工程当前的三块板子：

| 板子 | NODE_TAG | NODE_MODEL | 测什么 | 固件文件 |
| --- | --- | --- | --- | --- |
| 节点1 | N01 | MQ-135 | 空气质量（氨气 / 苯 / 烟雾等） | deploy\fw\N01_MQ-135.hex |
| 节点2 | N02 | MQ-137 | 氨气 NH3 | deploy\fw\N02_MQ-137.hex |
| 节点3 | N03 | MQ-2 | 可燃气体 / 烟雾 | deploy\fw\N03_MQ-2.hex |

```powershell
cd "D:\smoke-alarm\04"
powershell -ExecutionPolicy Bypass -File .\tools\build_node.ps1 -Tag N01 -Model "MQ-135" -Out .\deploy\fw\N01_MQ-135.hex
powershell -ExecutionPolicy Bypass -File .\tools\build_node.ps1 -Tag N02 -Model "MQ-137" -Out .\deploy\fw\N02_MQ-137.hex
powershell -ExecutionPolicy Bypass -File .\tools\build_node.ps1 -Tag N03 -Model "MQ-2"   -Out .\deploy\fw\N03_MQ-2.hex
```

> **NODE_MODEL 不只是显示文字**：节点把它放进信息帧上报，网关再交给触摸屏，屏幕按型号决定
> "这组读数是什么意思"（对照表在 `cyd_gateway\main\ui.c` 的 `s_sensors[]`）。
> 型号写错或漏写，屏幕上会退回兜底的"气体浓度"文案。
>
> 三种传感器的读数含义是同一种：**Rs 越小 → 被测气体越浓**；Δ% 是 Rs 相对自适应基线的
> 变化率，所以 **Δ% 越负表示浓度越高**（判据取绝对值，阈值 `NODE_ALARM_PCT`）。

其余参数（报警阈值、上报周期、引脚、供电/分压）在同一个文件里，都带注释；
三块板只要接线方式一致就共用同一套参数，不需要分别改。

## 4. 典型部署（一间房一个节点）

```
                ┌────────────── 节点1  N01 (MQ-135) ── 距网关 3m
                │
   触摸屏网关 ◄──┼────────────── 节点2  N02 (MQ-137) ── 距网关 1m
   (CYD)        │
                └────────────── 节点3  N03 (MQ-2)   ── 距网关 6m，隔一堵墙
```

> 触摸屏（CYD）和 ESP32-S3 跑的是同一套网关逻辑：屏幕上按每个节点的 NODE_MODEL 显示
> "传感器型号 + 该型号的数据含义 + 数值"。工程最多支持 4 个节点（APP_MAX_NODES），
> 以后加第 4 块板子照 §3 再编一份固件即可。
```

摆放建议：

* 传感器朝下/侧面，别被柜子挡住；厨房节点避开油烟直冲的位置（否则天天报警）；
* 网关尽量放在屋子中间、离地 1m 以上（金属箱里信号会差很多）；
* 节点上电后 **30 秒预热期**（`NODE_WARMUP_MS`）内不报警，预热结束时蜂鸣器会"嘀"一声；
* 全新 MQ 系列传感器（**尤其 MQ-135 / MQ-137**）要**连续通电 24~48 小时**基线才稳定，
  答辩前一天最好一直通电；刚上电时 Δ% 乱跳是正常的，等预热 + 基线稳定后再测。

## 5. 用打火机测试（请务必按这个来）

1. **不点火**，按住打火机喷嘴，在传感器上方 **2~3cm** 处放丁烷 **2~3 秒**
   （丁烷比空气重，从上面压下去最有效）；
2. 合格标准：2~5 秒内 Δ% 变化 **≥30%**（通常是负值），30~60 秒回落；
3. 这一步会真的触发报警：蜂鸣器响、网页变红、事件流出现"报警"；松手后约 1 分钟自动解除。

> 也可以用酒精棉球/香烟烟雾测，但**别用明火**，MQ 系列传感器对明火很敏感，容易烧坏敏感膜。

## 6. 常见接线故障对照

| 现象 | 原因 |
|---|---|
| 串口一行都没有 | 串口接错脚；正确是 **PB7(TX) / PB4(RX)**，115200；接反 TX/RX 也是这个现象 |
| 数值不动 / 一直是 0 | AO 是不是接到了 PA4（不是 PB4 那个串口脚）；地线有没有共地 |
| ADC 一直是 4095 | 5V 供电但没分压，或 `NODE_AO_DIV_X100` 填错 |
| ADC 一直是 0 / Rs=999999 | AO 线松了、模块没供电 |
| 数值乱跳 | 地线没共地，或传感器离电源/电机太近 |
| 蜂鸣器一直响 | 报警没解除（真的闻到东西了），或者 `NODE_BUZZER_ACTIVE_HIGH` 接反 |
