## 1. 节点固件（CH573F）

### 1.1 用 MounRiver Studio 2（推荐，能在线调试）

1. 打开 MounRiver Studio 2 → `File` → `Import` → `Existing Projects into Workspace`；
2. `Select root directory` 选到
   `...\04_毕设项目_家庭室内多节点烟雾报警系统\node_ch573f\node\SmokeNode`
   （选**工程目录本身**，不要选它的上级）；
3. `Finish`，工程名会显示为 `SmokeNode`；
4. `Project` → `Build`（或锤子图标）；
5. WCH-LinkE 接好 SWD（SWCLK/SWDIO/GND/3V3），`Project` → `Download`。

> **依赖目录不能移动**：工程用相对路径找 `..\HAL`、`..\LIB`、`..\..\SRC`。

## 2. 网关固件（ESP32-S3）

### 2.1 改配置

`gateway_esp32s3\main\app_config.h`：

```c
#define APP_WIFI_SSID      "YOUR_WIFI_SSID"        /* 家里 WiFi / 笔记本热点 */
#define APP_WIFI_PASSWORD  "YOUR_WIFI_PASSWORD"
#define APP_MQTT_URI       "mqtt://192.168.137.1:1883"   /* 见 start.ps1 打印 */
#define APP_MQTT_USERNAME  "esp32gw"
#define APP_MQTT_PASSWORD  "CHANGE_ME_DEVICE_PW"
#define APP_MAX_NODES      4               /* 你有几个节点就写几（1~6） */
```

> `APP_MQTT_URI` 的 IP 必须等于"跑服务器那台电脑在这个网络里的地址"。
> 运行 `server\start.ps1` 会把它打印出来；用笔记本移动热点时通常是 `192.168.137.1`，
> 用家里路由器时可能是 `192.168.1.100`（本机实测就是 `192.168.1.100`）。

改了 `APP_MAX_NODES` 要同步改 `sdkconfig.defaults` 里的 `CONFIG_BT_ACL_CONNECTIONS`
（建议 = 节点数 + 1），然后加 `-FullClean` 重新编译一次。

### 2.2 编译 / 烧写

```powershell
# 只编译
powershell -ExecutionPolicy Bypass -File .\tools\build_gateway.ps1

# 编译并烧写（COM8 换成你的串口）
powershell -ExecutionPolicy Bypass -File .\tools\build_gateway.ps1 -Port COM8 -Flash

# 烧完顺便打开串口监视器（Ctrl+] 退出）
powershell -ExecutionPolicy Bypass -File .\tools\build_gateway.ps1 -Port COM8 -Flash -Monitor
```

成功时：

```
smoke_gateway.bin binary size 0x144430 bytes. Smallest app partition is 0x300000 bytes.
```

> **脚本会自动选编译位置**：工程在纯英文路径（当前是 `D:\smoke-alarm\04`）时**直接原地编译**，
> 和手工敲 `idf.py build` 完全一样；只有把工程放回中文目录时，才会先同步到
> `D:\A_ESP32_project\smoke_gateway_build` 再编译（源码永远以工程目录为准）。
>
> **VS Code 里要打开 `gateway_esp32s3` 这个文件夹**，不要打开工程根目录 `04`：
> ESP-IDF 扩展把"打开的文件夹"当成固件工程，根目录下没有 `CMakeLists.txt`，
> 会报 `The source directory "D:/AAA_BSXMJ/04" does not appear to contain CMakeLists.txt`。
> 打开 `gateway_esp32s3` 后，扩展里的 Build / Flash / Monitor 都能直接用（里面已经配好
> `idf.adapterTargetName=esp32s3` 和 `COM6`），也可以按 `Ctrl+Shift+B` 用配套任务。

#### 2.2.1 为什么不能在中文目录里直接 `idf.py build`（VS Code 的 Build 按钮同理）

这不是代码问题，是**工具链在中文路径下的两个硬限制**，实测报错是这样递进的：

**第一关：Python 的 GBK 编码**

```
UnicodeDecodeError: 'gbk' codec can't decode byte 0xae in position 6116: illegal multibyte sequence
  File ".../tools/kconfig_new/prepare_kconfig_files.py", line 94, in main
    env.update(json.load(args.env_file))
CMake Error at .../tools/cmake/kconfig.cmake:176 (message):
  Failed to run kconfgen
```

ESP-IDF 的 kconfig 工具是 Python 写的，在中文 Windows 上默认按 **GBK** 读写它自己生成的
`build/config.env`、`project_description.json`（其中含有中文路径），于是解不出来。

**第二关：ninja 只认 ANSI 路径**（把第一关用 `PYTHONUTF8=1` 绕过后就会撞上）

```
ninja: error: FindFirstFileExA(d:/a_a_a_姣曡椤圭洰闆?04_姣曡椤圭洰_.../build/cmakefiles/cmaketmp):
       文件名、目录名或卷标语法不正确。
CMake Error at .../CMakeLists.txt:234 (message):
  Failed to determine sizeof(time_t)
```

ESP-IDF v5.1 自带的 ninja 1.10.2 用的是 Windows 的 **ANSI 版文件 API**，
中文路径传进去就变成了乱码，连最基本的"试着编译一个头文件"都过不去。

**两种解决办法（二选一）**：

| 办法 | 做法 | 适合 |
|---|---|---|
| ✅ 用镜像脚本（当前方案，已验证可用） | 命令行跑 `tools\build_gateway.ps1`；VS Code 里按 `Ctrl+Shift+B` 选「编译网关(英文镜像)」 | 想保持工程目录名不变 |
| ✅ 把工程搬到纯英文目录 | 例如整个工程放到 `D:\smoke_alarm\`，之后 VS Code 里的 Build / Flash / Monitor / 调试都能直接用 | 想用 ESP-IDF 扩展的全部功能 |

> 工程里已经加了两层保护：`gateway_esp32s3\CMakeLists.txt` 开头会设置
> `PYTHONUTF8`（绕开第一关），`gateway_esp32s3\.vscode\` 里有现成的
> `settings.json`（指定 esp32s3 / COM6）和 `tasks.json`（一键编译、编译+烧写）。

## 3. 服务器（PC 端）

### 3.1 一次性初始化

```powershell
cd server
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

它会：
* 用系统 Python 建 `.venv`，**离线**安装 `paho-mqtt`；
* 生成 Mosquitto 的密码文件、ACL、主配置；

> Mosquitto 在 Windows 上**不支持中文路径**。当前工程在纯英文路径下，所以这些文件就放在
> `server\mosquitto\` 里，整个工程自包含；如果哪天把工程挪回中文目录，setup.ps1 会自动
> 退回用纯英文运行目录（默认 `D:\A_ESP32_project\smoke_alarm_server`）。
> 两种情况都记在 `server\runtime.json`，`start.ps1` 照它启动；项目的 `config.json` 依然是唯一配置源。
> 想自己指定位置：设环境变量 `SMOKE_SERVER_DIR` 后重跑 setup.ps1。

### 3.2 每次使用

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1        # 启动
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Stop   # 停止
powershell -ExecutionPolicy Bypass -File .\start.ps1 -ShowLog # 另开窗口看日志
```

## 4. 整机联调顺序（推荐按这个顺序，出问题好定位）

| 步骤 | 做什么 | 怎么确认成功 |
|---|---|---|
| 1 | 只给**一个节点**上电，串口看日志 | 能看到每秒一行的 `[NODE ...]` 数据 |
| 2 | 打火机测试该节点 | Δ% 掉 30%+，串口出现报警行 |
| 3 | 节点断电，插上**网关**，看网关串口 | 出现"发现节点 / 物理连接已建立 / 已订阅遥测通知" |
| 4 | 再给节点上电 | 网关串口每秒/每 2 秒打印 `↑ tele {...}` |
| 5 | 电脑跑 `server\start.ps1` | 打印网页地址、访问口令、本机 IP |
| 6 | 打开 `http://127.0.0.1:3000` | 看到节点卡片（在线、Δ%、Rs、信号） |
| 7 | 打火机再测一次 | 网页变红、事件流出现"报警"，松手后出现"解除" |
| 8 | 网页点"消音 60s" | 事件流出现"回执"；节点串口打印 `mute for 60000 ms`（接了蜂鸣器的话此时停响） |
| 9 | 依次把其余节点上电 | 卡片数量增加到 = 节点总数 |
| 10 | 手机用流量打开隧道域名 | 和电脑上看到一样的页面 |

## 5. 故障排查表

| 现象 | 可能原因 / 处理 |
|---|---|
| 节点串口无输出 | 接反 TX/RX；波特率不是 115200；串口脚应为 PB7(TX)/PB4(RX) |
| MounRiver 报找不到 `CH57x_*.c` / `Link.ld` | `node_ch573f\SRC` 或 `node\HAL`、`node\LIB` 被移动/改名了 |
| MounRiver 报 `file format not recognized` / `dangerous relocation` | 实时防护改写产物，`Project → Clean` 后重新 Build |
| 网关串口一直 `WiFi 断开, 重连` | WiFi 名/密码错；热点是 5GHz（必须 2.4GHz） |
| 网关串口 `MQTT 断开` | PC 没跑 `start.ps1`；`APP_MQTT_URI` 的 IP 不对；防火墙拦 1883 |
| 网关找不到节点 | 两端广播名不一致；节点还在广播但距离太远（看 RSSI） |
| 网页显示网关离线 | `start.ps1` 起来了但 ESP32 没连上 MQTT；看 `logs\backend.err.log` |
| 网页里节点一直离线 | 网关没连上该节点，或节点掉电；看网关串口状态表 |
| Mosquitto 启动就退出 | 中文路径问题，确认 `server\setup.ps1` 跑过、`runtime.json` 存在 |
| 手机打不开公网地址 | 域名/隧道没配好，或没联网；先用局域网 IP 试 |
| 防火墙拦截 | 管理员 PowerShell 执行一次：<br>`New-NetFirewallRule -DisplayName "MQTT 1883" -Direction Inbound -Protocol TCP -LocalPort 1883 -Action Allow`<br>`New-NetFirewallRule -DisplayName "Web 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow` |

## 6. 验收清单（答辩前照着点一遍）

- [ ] 节点数 ≥3，每块板子的 `NODE_TAG` 不同（网页上能看出是哪个房间）
- [ ] 每个节点的 Δ% 在洁净空气中稳定在 ±10% 以内
- [ ] 用打火机测试：任意节点 2~5 秒内报警，串口出现 `>>> [NODE ...] 报警!`（接了蜂鸣器则同时响）
- [ ] 网页 2 秒内变红，事件流出现"报警"；松手约 1 分钟出现"解除"
- [ ] 网页"消音 / 自检 / 复位"都能在事件流看到回执；节点串口分别打印 `mute for 60000 ms` / `self test` / `alarm latch cleared`
- [ ] 拔掉一个节点：网关串口提示断开、网页 90 秒内变离线；插回去能自动重连
- [ ] 网关断电：节点本地仍然报警（串口 `>>> 报警`、接蜂鸣器则响）；网关上电后自动恢复上报
- [ ] 手机用流量（不是 WiFi）打开隧道域名，能看到同样的页面
- [ ] `selftest.py` 全部通过
