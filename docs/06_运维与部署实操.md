# 家庭室内多节点烟雾报警系统

> **一套真正跑起来的毕业设计实物**
> `CH573F 最小系统板 + MQ 传感器 + 蜂鸣器`（每个房间一个节点）
> → `BLE` → `ESP32-S3 网关` → `WiFi / MQTT` → **阿里云服务器** → 手机 / 电脑网页
>
> * 节点实物就三样：**CH573F 最小系统板 + MQ 传感器 + 有源蜂鸣器**（没有 OLED、没有按键，固件里也不含这两部分代码）
> * **报警判定在节点本地完成**，断网、断服务器都照样响
> * **服务器已经部署在阿里云**，日常使用**不需要打开本地电脑**
> * 网页能看实时数值、Δ% 曲线、报警记录，也能下发**消音 / 自检 / 复位**

```
   │ MQ-2 + 蜂鸣器│              │
   └──────────────┘              ▼
   ┌──────────────┐      ┌─────────────────┐   WiFi      ┌───────────────────────────┐

   │ MQ-2 + 蜂鸣器│      │ ① 扫描/连接节点 │   MQTT      │  192.0.2.10 (Ubuntu22) │
   └──────────────┘      │ ② 校验/解析帧   │   1883      │  ├ Mosquitto MQTT 服务器  │
   ┌──────────────┐      │ ③ 转 JSON 上云  │             │  ├ 后端 app.py (:3000)    │
   │ CH573F 节点3 │ ───► │ ④ 转发云端指令  │             │  ├ SQLite iot.db（历史）  │
   │ MQ-2 + 蜂鸣器│      └─────────────────┘             │  └ Cloudflare 隧道        │
   └──────────────┘            ▲                         └─────────────┬─────────────┘
                               │ BLE 写 0xFFE3                         │ HTTPS
```

**节点编号**：每块 CH573F 广播同一个名字 `SMOKE_NODE`，网关按 MAC 区分；
网页自动分配 `A / B / C / D` 标签，同时显示你烧固件时填的 `NODE_TAG`（如 `N01`、`厨房`），
所以建议**每块板子烧之前改一下 `NODE_TAG`**，答辩时一眼就能指出是哪个房间。

## 二、组网方式：为什么用 BLE 主从（星型），不用 Mesh / 广播

| 方案 | 能不能用 | 结论 |
|---|---|---|
| **BLE 主从（ESP32 做 Central，节点做 Peripheral）** | ✅ | **本工程采用**。ESP32-S3 一路一个 `gattc_if`，可同时连多台；CH573 协议栈本身就是外设角色，最稳最省事；每条链路都能双向通信（上报 + 下发） |
| BLE Mesh | ❌ | 沁恒 CH57x 协议栈**不提供 Mesh 模型**（无 provisioning / relay / 元素模型），自己实现等于重写协议栈；本场景节点少、距离近，Mesh 的收益用不上 |
| 纯广播（节点只广播、网关只扫描） | ❌ | ① 广播包最多 31 字节且无链路层确认，**丢包无法补救**；② 无法下发指令（消音/自检是刚需）；③ 节点不知道数据有没有被收到 |

一句话：**主从星型 = 双向可靠 + 实现代价最低**。
详细对比见 [docs/01_系统架构与组网方式.md](docs/01_系统架构与组网方式.md)。

## 四、日常使用（不需要启动任何服务器）

1. 手机 / 电脑打开 **https://smoke.example.com**，输入口令 → 看到大屏
2. 打火机测试（**不点火**，在传感器上方 2~3cm 放丁烷 2~3 秒）：
   节点蜂鸣器响 → 网页变红闪烁 → Δ% 曲线掉下去 → 事件流出现"报警"，松手约 1 分钟自动解除
3. 想消音：在网页上点 **消音 60s**（节点蜂鸣器停，事件流出现回执）
4. 想看直连是否正常：`http://192.0.2.10:3000`（需要安全组放行 3000）

> 💡 手机在后台/锁屏时网页会自动断开实时连接（省流量），回到前台自动续上，数据不会丢。
> 💡 页面看起来是旧样式时**刷新一次**即可（已加版本号做缓存刷新）；不要反复 Ctrl+F5 强刷（费流量）。

## 五、如果要重新烧写固件（换了板子 / 改了参数）

> 只有这一节需要打开本地电脑；已经跑通的系统**不需要动**。

### 第 0 步：环境自检（可选）

```powershell
cd "D:\smoke-alarm\04"
powershell -ExecutionPolicy Bypass -File .\tools\check_env.ps1
```

需要已装 **ESP-IDF v5.1.x**（编网关）和 **MounRiver Studio 2**（编节点）。
**本地不再需要 Python / Mosquitto**——服务器那部分已经在云上了。

> **VS Code 里请打开 `D:\smoke-alarm\04\gateway_esp32s3`**（不是工程根目录）。
> ESP-IDF 扩展把"打开的文件夹"当成固件工程；打开根目录会报
> `The source directory ... does not appear to contain CMakeLists.txt`。

### 第 1 步：节点固件（每块 CH573F 一块）

```powershell
# MounRiver Studio 2: File → Import → Existing Projects into Workspace
#   选 node_ch573f\node\SmokeNode → Build → WCH-LinkE 下载
# 或纯命令行编译（产物 node_ch573f\build\SmokeNode.hex）：
powershell -ExecutionPolicy Bypass -File .\tools\build_node.ps1
```

身份（节点编号 + 传感器型号）**不用改源码**，编译脚本直接覆盖，一条命令出一份固件：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_node.ps1 -Tag N01 -Model "MQ-135" -Out .\deploy\fw\N01_MQ-135.hex
powershell -ExecutionPolicy Bypass -File .\tools\build_node.ps1 -Tag N02 -Model "MQ-137" -Out .\deploy\fw\N02_MQ-137.hex
powershell -ExecutionPolicy Bypass -File .\tools\build_node.ps1 -Tag N03 -Model "MQ-2"   -Out .\deploy\fw\N03_MQ-2.hex
```

当前三块板子：**N01 = MQ-135（空气质量）、N02 = MQ-137（氨气 NH3）、N03 = MQ-2（可燃气/烟雾）**。
NODE_MODEL 会经网关传给触摸屏，屏幕按型号显示对应的**数据含义 + 数值**（对照表在
`cyd_gateway\main\ui.c` 的 `s_sensors[]`，详见 `docs\02`）。

### 第 2 步：网关固件（ESP32-S3，一块）

`gateway_esp32s3\main\app_config.h` 里 **MQTT 地址已经指向云服务器**，正常不用改：

```c
#define APP_MQTT_URI       "mqtt://192.0.2.10:1883"   /* 云服务器 */
#define APP_MQTT_USERNAME  "esp32gw"
#define APP_MQTT_PASSWORD  "与 server\\config.json 一致"
```

（同文件里还留着"笔记本本地调试"的注释行，需要离线演示时再切过去。）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_gateway.ps1 -Port COM6 -Flash -Monitor
```

串口看到 `WiFi 已连接` → `MQTT 已连接: mqtt://192.0.2.10:1883` 就成功了。

### 改了代码 / 样式之后怎么更新到云上

```powershell
# 本机改完 server\ 里的文件后，一条命令搞定：
powershell -ExecutionPolicy Bypass -File .\deploy\push_update.ps1
```

它会自动：**打包 → 在服务器上备份当前版本 → 上传 → 解压安装 → 自检**（服务状态 / 网页两条路径 / 前端版本号）。
安装脚本是幂等的，**数据库不会被动**；出问题可以用服务器上的
`/opt/smoke-alarm-backup-<时间戳>.tar.gz` 回滚（脚本会保留最近 3 份）。

> 改了网页样式/脚本，记得把 `server\web\index.html` 里的 `?v=` 数字 **+1**（用于刷新缓存）。

### 流量管理（免费额度完全够用）

| 措施 | 效果 |
|---|---|
| 后端 gzip 压缩 | 打开网页一次：1.16 MB → **383 KB（-67%）** |
| 页面切后台自动断开 | 手机锁屏 / 切走时**不再消耗流量** |
| 隧道改成 1 条 http2 连接 | 空闲流量从 47~437 MB/天 → **12 MB/天** |
| 静态资源长缓存（echarts 7 天） | 再次打开只加载几十 KB |

正常使用约 **0.5~1 GB/月**；ESP32 上报属于**入网流量，阿里云不计费**。
建议在控制台再加两道保险：**云监控 → 报警规则**（公网出方向流量阈值）、**费用中心 → 预算预警**。
详见 [deploy/README_部署到阿里云.md](deploy/README_部署到阿里云.md)。

## 七、数据是怎么流动的（写论文 / 答辩直接用）

| 环节 | 内容 | 代码位置 |
|---|---|---|
| ① 采集 | ADC 连续采样 16 次取平均 → `Rs = RL×(VCC−Vao)/Vao` → 与自适应基线比得 Δ% | `node_ch573f/.../APP/smoke_sensor.c` |
| ② 判定 | \|Δ%\| ≥ 25% 连续 2 次 → 报警；回落到 12% 以下连续 5 次 → 解除（迟滞防抖） | 同上 |
| ③ 本地动作 | 报警锁存 + 蜂鸣器断续响（唯一的本地输出）；串口打印报警/解除事件行 | `node_ch573f/.../APP/smoke_node.c` |
| ④ 上报 | 16 字节二进制遥测帧，**正常 2 s / 报警 0.5 s**，BLE Notify | `node_proto.h` / `smoke_node.c` |
| ⑤ 汇聚 | ESP32-S3 校验帧 → 转 JSON → MQTT 上报；报警跳变时另发事件 | `gateway_esp32s3/main/gateway_main.c` |
| ⑥ 上云 | WiFi + MQTT（遗嘱消息 + 断网缓存补发） | `gateway_esp32s3/main/wifi_mqtt.c` |
| ⑦ 存储 | SQLite 三表：`devices`（台账）+ `telemetry`（曲线，**2 秒一个点**）+ `events`（事件，保留 30 天） | `server/backend/app.py` |
| ⑧ 展示 | 网页：节点卡片（SSE ≈2 s）+ **Δ% 曲线每 2 秒增量刷新** + 报警统计 + 事件流；响应 gzip 压缩 | `server/web/*` |
| ⑨ 下发 | 网页 → MQTT → 网关 → BLE 写 0xFFE3 → 节点执行 | 全链路 |

MQTT 主题（`gw01` = `server/config.json` 里的 `gateway_id`）：

```
home/gw01/tele/<MAC>     遥测       节点 → 云
home/gw01/event/<MAC>    报警/解除  节点 → 云
home/gw01/state/<MAC>    在线状态    节点 → 云 (retained)
home/gw01/state/gateway  网关心跳    网关 → 云 (retained + 遗嘱)
home/gw01/ack/<MAC>      指令回执    节点 → 云
home/gw01/cmd/<MAC>      控制指令    云 → 节点
```

## 九、常见问题

| 现象 | 先查这里 |
|---|---|
| 网页打不开 | 手机用流量试 `https://smoke.example.com`；服务器上 `systemctl status smoke-backend cloudflared` |
| 网页能开但一直"网关离线" | ESP32 是否上电、串口是否 `MQTT 已连接`；服务器上 `journalctl -u smoke-mosquitto -n 30` 看有没有 `esp32gw-gw01` 连接 |
| 有网关、但节点卡片离线 | 网关串口看有没有 `物理连接已建立 / 已订阅遥测通知`；节点是否上电；距离是否太远（看 RSSI） |
| 节点串口没输出 | 串口接的是 **UART0：TX=PB7，RX=PB4**，115200；别把 AO(PA4) 当成 PB4 |
| 网关搜不到节点 | 两边广播名要一致（都是 `SMOKE_NODE`） |
| Δ% 一直在 ±20% 内乱跳 | 正常（漂移 + 噪声）；真正的气体事件是**几十个百分点**并触发报警 |
| 传感器几乎不响应 | MQ-2 加热丝要 5V 才够热；新传感器要连续通电 24~48 小时基线才稳 |
| 听不到报警声 | 蜂鸣器接 **PB15**（经三极管/驱动模块，高电平响）；没接就看串口 `>>> 报警` 行和网页横幅 |
| 域名打开是旧样式 | 刷新一次（HTML 已是 no-store）；仍不行就用无痕窗口 |
| 想在本机离线演示 | 见下面第十节 |

## 十、本机离线调试（可选，平时不用）

服务器虽然搬到云上了，本地这套仍然完整可用，适合**没网时演示**或**改服务器代码时先本地验证**：


* 本机网页：`http://127.0.0.1:3000`（口令同上）
* 只用本机时，把网关的 `APP_MQTT_URI` 换成本机地址（如热点 `192.168.137.1`）再重新烧写
* ⚠️ **同一套 Cloudflare 隧道 token 只能在一处运行**：本机要启动隧道前，先在云服务器上
  `sudo systemctl stop cloudflared`，否则域名会在两台机器之间轮询，出现"时而正常时而空白"
* 本机端到端自检（不需要任何硬件）：

## 十一、工程实现中踩过的坑（答辩素材）

| 问题 | 现象 | 解决办法 |
|---|---|---|
| **中文路径 + ESP-IDF** | `UnicodeDecodeError: 'gbk' codec ...` → `Failed to run kconfgen`；`ninja: FindFirstFileExA(...)` | ① CMakeLists 里预设 `PYTHONUTF8`；② 工程改到纯英文路径 `D:\smoke-alarm\04`（`build_gateway.ps1` 也能自动切英文镜像目录） |
| **中文路径 + Mosquitto** | 启动即退出：`Unable to open pwfile ...` | 运行文件放纯英文目录；纯英文工程下直接放 `server\mosquitto\` |
| **mosquitto 版本差异** | Ubuntu 22.04 的 mosquitto 2.0 报 `Error: Invalid max_keepalive value (0)` | 删掉 `max_keepalive 0`（2.1.2 接受，2.0 不接受） |
| **CDN 缓存导致样式不一致** | 域名访问是深色旧样式、IP 直连是浅色新样式 | 后端加 `Cache-Control`（页面/脚本 `no-store`、大库长缓存）+ `index.html` 里 `?v=` 版本号 |
| **未备案域名** | 域名解析到国内服务器走 80/443 会被拦 | 用 `IP:端口`，或走 Cloudflare 隧道（出站连接）提供 HTTPS |
| **隧道很费流量** | 空闲也要几十~几百 MB/天（4 条 QUIC 保活） | 改成 **1 条 http2 连接** → 实测降到 ~12 MB/天 |
| **网页首屏太大** | 1.16 MB（echarts 占 1.1 MB） | 后端 gzip → 383 KB；静态资源长缓存 |

更详细的报错原文与分析见 [docs/04_编译烧写与联调步骤.md](docs/04_编译烧写与联调步骤.md)
