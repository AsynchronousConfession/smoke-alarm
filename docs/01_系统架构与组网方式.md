# 01 系统架构与组网方式

## 1. 系统分层

```
感知层   CH573F + MQ 系列气敏传感器（每个房间一个节点）
         职责：采样 → 判报警 → 本地蜂鸣器 → BLE 上报
              ▲
              │ BLE 4.2（GATT，自定义 0xFFE0 服务）
              ▼
汇聚层   ESP32-S3 网关（BLE Central + WiFi STA）
         职责：多路连接管理 / 数据校验解析 / 报警跳变检测 / MQTT 上下行 / 断网缓存
              ▲
              │ MQTT 3.1.1（局域网 1883）
              ▼
平台层   笔记本上的三个小程序
         Mosquitto（消息代理） + backend/app.py（订阅入库 + REST/SSE + 静态网页）
         + cloudflared（内网穿透隧道）
              ▲
              │ HTTPS（Cloudflare 隧道，出站连接，不需要公网 IP）
              ▼
应用层   手机 / 电脑浏览器（大屏：卡片 + 曲线 + 报警统计 + 事件流 + 指令下发）
```

## 2. 为什么是"BLE 主从星型"而不是 Mesh / 广播

### 2.1 需求拆解

| 需求 | 说明 |
|---|---|
R1 | 多个节点（3~6 个）周期性上报模拟量（ADC/Rs/Δ%） |
R2 | 报警要**及时**（秒级），并且节点断网时本地照样报警 |
R3 | 云端要能**下发指令**（消音、自检、复位） |
R4 | 节点要便宜、代码要简单（CH573F 只有 18KB RAM，协议栈是闭源库） |
R5 | 毕设周期内要能真正做出来、讲得清楚 |

### 2.2 三种方案的对比

| 对比项 | 主从（星型） | Mesh | 纯广播 |
|---|---|---|---|
| CH57x 是否支持 | ✅ 原生外设角色 | ❌ 协议栈无 Mesh 模型（无 provisioner / relay / 元素模型） | ✅ Broadcaster 角色 |
| 可靠性 | 链路层 ACK + 重传，通知（Notify）可靠 | 多跳自愈，但依赖实现 | ❌ 无 ACK，丢包不可知 |
| 双向通信 | ✅ 每条链路可读写 | ✅ | ❌ 广播单向 |
| 汇聚点容量 | ESP32-S3 Bluedroid 一个 `gattc_if` 管一路连接，实测 3~4 路稳定 | 需要复杂路由表 | 扫描端可收很多 |
| 功耗 | 中等（连接间隔 7.5~125ms 可调） | 中高（要转发别人的包） | 最低 |
| 实现复杂度 | ★★ | ★★★★★ | ★★★（要自己设计包格式+重传） |
| 适合场景 | 单户住宅、节点离网关十几米 | 楼层多、距离远、节点多 | 只上报、不要下行 |

### 2.3 结论

采用 **BLE 主从星型**：

1. **够用**：家用室内最远十几米，BLE 4.2 在开阔室内 10~30m，中间隔一堵墙也能连上；实测 RSSI 在 -45 ~ -75 dBm 之间。
2. **可靠**：连接态有链路层 ACK/重传，节点还能通过 MTU/连接参数协商保证时延。
3. **双向**：消音/自检/复位这些指令必须能下发，广播方案做不到。
4. **能做完**：CH573F 的 BLE 协议栈只给你外设角色的 API，Mesh 需要自己实现，超出毕设合理范围。
5. **好扩展**：ESP32-S3 端 `APP_MAX_NODES` 改大即可（配套改 `CONFIG_BT_ACL_CONNECTIONS`），代码里每个连接一个 `gattc_if`，互不干扰。

> **答辩时的加分说法**：Mesh 的优势是"多跳+自愈"，代价是"每个节点都要会转发、要有路由表、要一直保持接收"。
> 本场景节点数少、距离近、有常电供电，多跳收益 < 复杂度收益，所以选星型；如果将来要做整栋楼
> （节点几十个、跨层），才值得换成 Mesh 或"星型 + 中继节点"的混合结构。

## 3. 地址与标识设计（三层 ID）

| 层 | 标识 | 谁分配 | 用途 |
|---|---|---|---|
| 物理 | BLE MAC（如 `AA:BB:CC:DD:EE:FF`） | 芯片出厂 | BLE 连接、MQTT 主题里的唯一键 |
| 网络 | 网关 ID `gw01` | `server/config.json` | MQTT 主题前缀 `home/gw01/...` |
| 业务 | 标签 `A/B/C/D` + `NODE_TAG`（`N01`/`厨房`） | 后端自动分配 / 烧固件时填 | 网页显示，人看得懂 |

这样做的好处：**换板子不用改服务器**——新板子插上就自动建台账；同一个房间换了板子，
把 `NODE_TAG` 烧成一样的值，网页上看到的还是"厨房"。

## 4. 时序（一次报警的完整旅程）

```
节点 smock_sensor      节点 smoke_node        网关 gateway_main       服务器 backend        网页
      │ 每 500ms 采样        │                       │                    │                 │
      │── Δ% 超阈值 ────────► │                       │                    │                 │
      │                       │    蜂鸣器立即动作       │                    │                 │
      │                       │── 16B 遥测帧(0.5s/次) ►│                    │                 │
      │                       │                       │ 校验 → 报警跳变     │                 │
      │                       │                       │── tele + event ───►│ 入库 + SSE      │
      │                       │                       │                    │── 事件推送 ───► │
      │                       │                       │                    │                 │ 红色横幅
      │                       │                       │                    │◄── 点"消音" ──── │
      │                       │◄── BLE 写 0xFFE3 ─────│◄── cmd/MAC ────────│                 │
      │ 静音 60 秒(仍上报)     │                       │                    │                 │
      │                       │                       │── ack/MAC ────────►│ 事件流显示回执    │
```

时延估算（局域网）：采样→判定 ≤ 0.5s，BLE 通知 ≤ 1 个连接间隔（本工程 15~125ms），
MQTT 局域网 ≤ 50ms，SSE 推送 ≤ 1s。**从冒烟到网页变红，通常 1~2 秒**。

## 5. 可靠性与异常处理

| 异常 | 系统行为 |
|---|---|
| 节点掉电/走远 | 连接断开 → 网关立即把该节点标记离线（retained 状态），并继续扫描重连；网页 90 秒无数据也会兜底置离线 |
| 网关掉电 | 节点本地继续采样和报警（串口打 `>>> 报警`，接了蜂鸣器也会响），只是不上云；网关重启后自动重连节点 |
| 家里断网 | 网关照常收节点数据，MQTT 发布失败进入**断网缓存**（默认 32 条），恢复后补发；云平台用心跳超时判定网关离线 |
| 电脑关机 | 数据只在电脑开机时入库；节点侧无历史回放（这是家用方案的固有代价，见 `docs/05` 的改进方向） |
| 数据帧出错 | 帧尾有校验和，校验失败直接丢弃并打日志；序号可用来粗查丢包 |

## 6. 扩展方向（答辩"如果让你继续做"）

1. **节点加传感器**：MQ-2 换成 MQ-135（空气质量）、MQ-7（CO）等，只在 `node_cfg.h` 改型号与阈值；
2. **网关加本地存储**：ESP32-S3 挂 SD 卡或 SPIFFS，断网时缓存更久（现在只有内存 32 条）；
3. **多网关**：`gateway_id` 换成 `gw02`，云端按网关分组，天然支持两层楼；
4. **告警外呼**：后端加一个 webhook，报警时推微信/钉钉/短信；
5. **低功耗节点**：节点改成"定时唤醒上报"，配合 BLE 从机的 `HAL_SLEEP`，可做电池版。
